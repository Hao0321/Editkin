# OpenCode Agent 側欄 UI/UX 藍圖

日期：2026-09-29。範圍：Editkin 桌面剪輯台的 Agent 側欄；保留官方 OpenCode ACP 核心與現有剪輯工具管線。

## 使用情境

創作者正在看預覽或時間軸，想用自然語言交代剪輯任務，並在同一視窗檢查 Agent 的進度、工具操作與結果。側欄寬度可能只有 300–380 px；主畫面仍須留給影片。

## 當前畫面 Review

1. 上方連續出現「OpenCode Agent／對話與工具／新對話／＋新對話」，資訊重複，真正的專案脈絡和模型反而以 11 px 小字呈現。
2. 空對話把大半側欄留白，只有一句抽象提示，第一次使用者不知道可以交代何種任務。
3. 輸入框底部同列放附件、原生模式、長模型名稱及傳送鍵；窄側欄會截斷模型識別，按鈕目標偏小。
4. 工具卡顯示 `editkin_call_editkin_tool` 這類內部名稱，使用者難以快速辨認「做了什麼、完成了嗎」。原始資訊仍必須可展開，供審查。
5. 設定中的技能與工具數量是進階資訊，應維持次要層級；準備、執行、失敗與衝突狀態要在同一個穩定版面中呈現。

## 新版結構

由上到下固定為：

1. **工作區標題**：`Agent` 為主標、`OpenCode` 為來源標示；右側只放收合。
2. **工作區分頁**：`對話`、`編劇`、`素材`。分頁只切內容，不暗示另開服務。
3. **對話工具列**：目前對話標題；`新對話` 與 `歷史` 各有一個明確入口。
4. **專案脈絡**：目前 Editkin 專案名稱和 `草稿／已儲存`、`處理中／可剪輯` 狀態；不以連線術語描述正常狀態。
5. **對話區**：空態提供兩個可編輯的示例指令；進行中的工具以人能理解的標題與狀態呈現，技術內容收在展開區。
6. **固定輸入區**：選取片段引用、附件、文字輸入；底行清楚區分「模式」與「模型」，傳送／停止有足夠的點擊尺寸。設定折疊於最後。

## 互動規則

- 示例指令只填入輸入框，絕不自行送出或操作時間軸。
- 模型選單保留 OpenCode 公告的原生選項；窄寬度下可用 `title` 看全名，畫面不產生水平捲動。
- 工具卡先讀到動作與完成狀態，展開後仍可看到 OpenCode 的原始工具名稱、結果、diff 與位置。
- 側欄在準備中仍可撰寫草稿。錯誤、授權及衝突維持可見且有明確操作。
- 跟隨 Editkin 的 sky/candy/volt 主題與字體；不新增設計套件或獨立 Agent 配色。

## 驗收

- 300、380、560 px 側欄寬度：標題、模型、模式、傳送鍵和專案脈絡可見，無水平溢出或遮擋。
- sky/candy/volt：文字、表單與主操作保持可辨識；空態和真實工具結果均實際看圖。
- 測試新建／歷史對話、長回覆、剪輯台工具讀寫、收合後繼續工作、Undo；UI 改版不得改變這些行為。
- 預覽 EXE 的桌面截圖與報告保存於 workspace `artifacts/autopilot-desk/`，區分 UI 驗證與真實區網模型或 Kit v4 成片驗證。

## 本輪落地與 Review

- 側欄分頁縮為「對話」；目前對話、專案名稱與狀態各佔固定位置。空對話首屏顯示「盤點專案」及「規劃節奏／分析片段」兩個起點，點擊只填入草稿並聚焦輸入框。
- 模式與模型各有標籤，附件和傳送留在獨立一行；在 300／380／560 px 寬度檢查選單、傳送鍵與內容均未溢出。長模型名稱可從選單與滑鼠提示看完整文字。
- 工具卡先呈現動作與狀態，原始 OpenCode 工具名稱和結果留在「查看操作紀錄」。當 ACP 只回傳通用 gateway 名稱、未提供內部動作時，卡片仍只能顯示「剪輯台工具」；不從結果猜測具體操作。
- 空對話捲到頂端，讓起點在第一次開啟時可見；有訊息時跟隨最新內容。volt 主題的原生表單與捲軸採深色系統樣式，定義放在共用主題檔並通過主題一致性檢查。
- 隔離桌面實測涵蓋三套主題、三種側欄寬度、首屏起點、草稿不自動送出、長串流、歷史會話、工具讀寫、收合後同步及 Undo。測試使用短暫 loopback 假模型；真實區網 Qwen、原版 OpenCode Web 前端及 Kit v4 完整剪片仍須分別驗收。

## 精簡側欄第二輪（使用者截圖 Review，2026-09-29）

前一輪雖修正資訊名稱，卻仍把品牌、分頁、對話標題、專案狀態、空態說明、模型設定與快捷鍵排成多個常駐區塊。側欄在常見高度只剩很短的對話視窗；這次以**可讀對話面積**作為首要指標。

對照：[Claude Code Desktop 官方文件](https://code.claude.com/docs/en/desktop)把模型、權限模式放在傳送鍵旁，附件入口放在輸入框旁，會話與專案各有清楚脈絡；[Codex App 官方介紹](https://openai.com/index/introducing-the-codex-app/)強調按專案整理會話及在對話內檢查 Agent 變更。Editkin 因此讓模型／模式貼近傳送、對話保留最大面積，並把剪輯工具結果留在同一串對話中供查看。這是結構參考，並未宣稱複製兩款產品的完整功能。

1. 頂部縮成同列「Agent／OpenCode／收合」，分頁維持一行但降低高度。對話標題與新建、歷史、更多操作同列；不再另佔一行顯示專案狀態。
2. 「更多」開啟不推擠對話的浮層，顯示目前專案、草稿／工具狀態、區網模型位址、技能與 session 資訊。專案名稱同時放進浮層入口的提示與無障礙標籤；正常情況下不常駐顯示「可剪輯」。連線失敗、儲存衝突與授權要求仍留在主畫面。
3. 空態只留一句引導與兩個可編輯任務起點；已經有對話時完全消失。新建與歷史是圖示按鈕，仍保留明確 `aria-label` 和滑鼠提示。
4. 輸入框內保留模型、模式、附件和傳送；模式／模型選單合併到底行，移除常駐說明文字與快捷鍵。文字框的提示和 `title` 承載快捷鍵；選取片段只顯示短標籤，完整名稱與秒數放提示。
5. 以 300、380、560 px 與 sky/candy/volt 實際看圖；檢查對話區高度、浮層不改變佈局、模型可點、歷史可載入、工具讀寫與 Undo。不用沒有實測的「像原版」宣稱替代畫面驗收。

### 完成與量測

- 工作區分頁已併入頂部工具列；新對話、歷史與更多操作位於對話標題同列。專案名稱、草稿狀態與進階設定移入浮層，技能清單、區網模型位址與診斷資訊各自收合。
- 空態刪去多餘說明，只留短引導與兩個起點。選取片段縮成短標籤，素材名稱與秒數由滑鼠提示顯示。模式、模型、附件與傳送共用輸入框底行，快捷鍵放在輸入框提示。
- 隔離桌面量測：固定頂部 83 px、輸入區 88 px、對話區 374.5 px；「更多」初開高度 189.5 px，開啟時對話區仍為 374.5 px。300／380／560 px 寬度及三套主題的控制項可見，長串流、歷史、工具讀寫、收合、Undo 與重新同步均通過。這些尺寸來自測試視窗，其他螢幕高度仍會按 flex 版面縮放。

## 長時間使用的互動修正（2026-09-29）

- Agent 串流時，使用者往上閱讀就停在原處；只有原本位於底部時才跟隨新內容。離開底部後顯示「最新訊息」入口，一鍵回到底部。切換會話或自行送出新任務時重新跟隨。
- 輸入長任務時文字框依內容長高，達上限才在框內捲動；送出後回到緊湊高度。避免使用者手動拖拉、也避免短句長期佔大面積。
- 「更多」與歷史浮層支援點擊外部或 Escape 關閉；兩者互斥。保留鍵盤可操作的觸發鈕與既有 session/tool/Undo 行為。
- 驗收須在桌面視窗操作，而不只檢查 CSS：途中上捲的串流不應跳到底部；長草稿會長高；浮層可自然退出。

### 桌面量測與結果

- 慢速串流進行中把對話捲到頂端後，直到回合完成 `scrollTop` 仍為 0；內容可捲動距離為 714 px。點「最新訊息」後到達 714 px 並恢復跟隨，桌面截圖已檢查按鈕位置。
- 草稿文字框由 48 px 自動長到 124 px，送出後回到緊湊高度。更多選單點擊外部關閉；歷史清單按 Escape 關閉；原有的會話、工具與復原桌面流程仍通過。

## 長任務輸入與授權可見性（2026-09-29）

- Agent 執行時仍可撰寫下一則草稿；送出鍵維持不可用，停止鍵不會清掉草稿。回合完成後才可傳送，沒有暗中排隊送出。
- 對話中的工具授權可能被後續輸出推離視野。只要 ACP 報告待授權 ID，輸入區上方就顯示短提示；「查看授權」會捲到相應卡片並把鍵盤焦點移過去。授權完成後提示消失。
- 對話尾端的執行狀態優先顯示待授權，其次顯示正在執行的工具名稱，最後才使用通用處理提示。此狀態只來自 ACP 回報，不推測工具是否成功。

## 對話辨識與紀錄閱讀（2026-09-29）

- OpenCode 尚未提供有意義的 session 標題時，側欄暫用第一則使用者任務作為對話標題；載入舊 session 也從重播事件恢復。OpenCode 提供正式標題後仍以原生標題為準。
- 歷史清單的長標題固定在單行截字，完整內容可由滑鼠提示查看；300／380 px 側欄不產生水平捲軸。
- 正常 `end_turn` 不佔對話列；停止、失敗及長度限制仍顯示可讀狀態，不在主畫面暴露原始協定字串。

## 原生指令輸入（2026-09-29）

- 輸入 `/` 時顯示 OpenCode 公告的指令，清單浮在輸入框上方，不縮小對話閱讀區。窄側欄採指令名稱與簡短說明兩行，長字串截字。
- 上下方向鍵移動選取，Enter 將指令填入草稿並保留游標，Escape 收起建議；選取指令不會自行送出模型請求。
- 隔離桌面以 300 px 側欄實際看圖，並確認清單不溢出、對話區高度不變，原有 Agent 工具流程仍可完成。

## 工具卡可審查的動作摘要（2026-09-29）

- `apply_edit_commands` 的主標仍是「修改時間軸」，下方增加從白名單命令推得的「要求：…」。單筆已知命令可顯示「片段音量設為 65%」「重新命名專案」等；多筆只顯示數量，未知命令顯示通用名稱。
- 摘要只描述 Agent 送出的要求，不代替工具結果與是否成功的判斷。專案路徑、片段 ID、專案名稱及未列入白名單的原始參數不會複製到摘要；原本的操作紀錄仍可展開檢查。
- 官方內附 OpenCode／隔離模型替身／真實 Editkin gateway 的桌面流程確認工具卡摘要、完成狀態、工作副本寫入與 Undo。300 px 畫面確認卡片不產生橫向捲動；原有長串流、會話、授權提示及預覽流程同次通過。

## 大型外部素材的工作進度（2026-09-29）

- 超過 64 MiB 的專案外來源由 `run_kit_workflow(create)` 回傳準備 ID；Agent 用同一工具的 `source-status` 查目前的讀取、複製、驗證階段。側欄卡片使用「查看素材準備進度」和「要求：複製素材 · 20%」一類短摘要，狹窄側欄不常駐完整路徑或 JSON。
- `source-cancel` 只在 Kit controller 建立 run 前可用；重啟後的 `source-resume` 重新核對專案與來源。若 controller 階段中斷，狀態明示結果待查證，不能直接重送。
- 目前進度由 Agent 查詢時更新，尚無獨立於對話工具的常駐自動進度列。百分比是來源副本準備的預估讀寫量，不代表剪片或輸出進度。

## 素材準備自動顯示與停止（2026-09-29）

- Agent 側欄原本只在模型查詢 `source-status` 時更新。現在沿用側欄既有的一秒狀態輪詢，從目前專案工作紀錄取得階段與估計百分比；只在準備、建立或需處理的中斷／錯誤狀態顯示緊湊列，完成後收起，不長期佔用對話面積。
- OpenCode 回合已結束而來源副本仍在準備時，進度列保留「停止」按鈕。它與對話中的停止鍵共用取消入口，向該工作送出限定 ID 的取消請求；準備程序讀到請求後中止。Kit controller 開始後，狀態改成「正在建立流程」，不再提供工作取消；當時的對話停止鍵明確標為「停止對話」。
- 以可攜 EXE 桌面畫面驗證 380 px 側欄顯示「複製素材 · 50%」、進度條與停止鍵，按下後顯示「正在停止素材準備」，controller 階段無工作停止鍵，沒有橫向溢出。這組畫面用隔離的工作紀錄測 UI；另以封裝 gateway 和 65 MiB 合成來源驗證實際跨程序取消與恢復。

## 素材準備完成後接續對話（2026-09-29）

- 背景準備完成、Agent 空閒時，側欄精簡顯示「素材已準備好，可接著剪輯」和「接著剪輯」。按鈕把自然語句放進草稿並聚焦輸入框，讓使用者檢查後傳送；不自行發起模型回合。
- 準備 ID 和精確的 Kit 狀態查詢只放入傳給 Agent 的上下文，不顯示在使用者草稿。只有送出成功才記住這份準備已接續；送出失敗會恢復草稿及接續綁定。清空草稿則可再看到接續入口。
- 桌面實測確認 380 px 側欄無水平溢出、按鈕不自動送出、失敗後草稿可重試，且實際傳給 Agent 的上下文綁定同一準備 ID。測試截住送出並檢查上下文，尚未證明區網 Qwen 可自主完成後續計畫。
