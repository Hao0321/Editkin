# Community collaboration

Editkin's ordinary editor is open source so people can fix bugs, improve accessibility, add formats, test platforms, and build compatible workflows together. The issue tracker is the task list. Maintainers will mark bounded issues with `good first issue`, `help wanted`, `security`, `documentation`, or `needs design`, and keep acceptance criteria in the issue. A contribution may come from one person or several people working through small pull requests.

The repository maintainer reviews and merges changes. Security-sensitive work receives an additional review from a designated trusted reviewer when one is available. This includes authentication, remote control, updates, installers, build workflows, process execution, plugins, Skills, dependency changes, and new external services. Public CI has no signing credentials; only a separate official release process can produce an official artifact.

Community Skills and plugins can be listed as compatible projects, but a listing is not a security endorsement. Editkin will not silently install, run, or update third-party code on a user's computer. Contributors should document required permissions and where data goes. A user chooses whether to install an integration.

Sponsorship can support maintenance, documentation, testing, and infrastructure. Independent contributors or teams may offer services around Editkin under their own names. This repository does not promise a paid edition or give sponsors control over technical decisions.
