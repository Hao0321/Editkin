# Editkin EXE 持續品質目標

此文件隨實際桌面驗收滾動更新優先順序與最終目標，也記錄發現的功能缺失與可增加部分。目標是讓封裝後的 Editkin 成為可理解、可編輯、可復原、可核查的本機剪輯工作台。每輪用封裝版確認行為，建立還原點、更新說明與交接說明，完成相稱清理，再按剩餘缺口調整下一輪目標。

## 第五十八輪滾動調整

使用者實際截圖指出所有供應商／API／登入模型平鋪難以選擇，確認先按供應商／來源分大項。主介面改為「本機、OpenAI／Codex、Claude、Gemini、Grok、OpenRouter、DeepSeek、OmniRoute」八項，再選該來源模型；登入、金鑰與連線管理留在設定，不出現在大項。

使用者接著指出展開的來源／模型表單佔版面，改為輸入框底下一列模式、來源／模型按鈕與傳送；點開按鈕才顯示八大項與模型。預設選單收合，Escape／點外面可關閉；未設定只留一行短提示與設定入口。未設定来源保留上一個原生模型、session、草稿與 working copy；按鈕／Enter 都不能暗中傳給上一個模型。來源未列入支援大項或找不到來源時有明確提示。刷新後需明確選擇新來源模型，不能把 catalog 當成帳號可用證據。

本輪以真正封裝的來源切換、設定導向、阻擋誤傳、視窗版面及原字幕／Undo／跨專案協定回歸驗收；真實 OmniRoute 部署與帳號額度的前輪界限保留。修正完成後回報，仍不推送 GitHub。

使用者要求介面不顯示 OpenCode 字樣：標題只保留 Agent，設定、回覆署名、授權／歷史／系統提示及可讀性標籤統一使用 Agent。內部 runtime 名稱、協定、帳號憑證與開源歸屬記錄保留，不改寫使用者文字或模型回答。

## 第五十七輪滾動調整

使用者要求本機、API、登入共用同一個Agent視窗，並評估接OmniRoute以涵蓋Claude、Codex、Grok、Gemini。新增外接閘道設定、native模型catalog、精確route前綴及工具能力門檻；仍使用原OpenCodeAgentDock、同一session／輸入框／ACP／MCP，不新增剪輯執行器。閘道設定與直接API／nativeChatGPT登入在同一設定面板，來源在同一模型選單標示。

OmniRoute可沿原生OpenCode adapter接線；本機沒有運行中的閘道，現npm包與Nodeengine條件也不適合直接當作已內建的服務。本輪只連接已啟動的服務，不全域升級或建立持久daemon。協定、版本研究、實際帳號驗收界限見`OMNIROUTE_INTEGRATION.md`。

本輪整合／驗收／清理及還原點完成後先回報，讓使用者決定是否整理提交原作者GitHub；目前不push／PR。不因持續goal自行展開其他客製功能；真實閘道部署、各家帳號額度／刷新與原作品真人審片仍待驗。

## 每輪先後順序

1. **功能與資料正確性**：匯入、預覽、時間軸、Agent 工具、存檔、重開、輸出與失敗後續跑。出錯時先停止不確定的變更，保留來源與已完成工作。
2. **任務完成度**：用封裝版、隔離工作區及具體素材驗證完整路徑。文字回覆、工具成功和 render 成功各自只證明其對應階段；成片還需解碼與真人審片。
3. **操作理解成本**：清除假的進度、重複控制和不符合實際能力的承諾；把目前狀態與下一步放在使用者正在工作的地方。
4. **視覺品質**：在常見桌面尺寸檢查層級、留白、字級、對比與可見範圍；以專業剪輯台的內容密度為準，不用裝飾掩蓋能力缺口。
5. **交付品質**：每輪保留型別／聚焦回歸、封裝後桌面 smoke、版本與 SHA-256、來源及封裝還原點、更新說明和絕對路徑交接。保留最新三個可執行版與正在使用的版本；其他版先驗證備份，若仍被 Kit run 綁定，保留原路徑的最小 Kit 來源。收尾核對本輪程序已退出並移除可重建測試快取。
